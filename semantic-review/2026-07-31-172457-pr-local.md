# CAPTCHA generation fencing remains incomplete (v3)

**Verdict**: NEEDS_CHANGES

<details>
<summary>Issues (3)</summary>

1. **Generation absent from browser response — confirmed** — Isolated-browser human-action responses normalize to generation `0`, excluding every canonical CAPTCHA pause from takeover. Expose and require the positive session generation in the strict response.
2. **Mismatch recovery zeros pause generation — confirmed** — A pre-action browser generation mismatch is projected as a new generation-zero pause before the takeover conflict is raised. Preserve the exact old pause or leave the ownership loss inert.
3. **Unread probe spends final-probe debt — confirmed** — `operation_in_flight` and `probe_failed` consume debt even though the decision requests another poll. Retain debt until a same-generation page observation completes.

</details>

## Findings

1. **BLOCKER — Canonical CAPTCHA pauses never receive the browser HITL generation — confirmed.** `SessionSummary` has no `hitl_generation` field and `ManagedSession.summary()` does not emit one (`browser_service/models.py:132-158`, `browser_service/session_manager.py:264-290`). The client reads only that nested field and defaults its absence to `0` (`ops/browser/service_client.py:503-512`); canonical persistence stores the zero (`ops/workflow/canonical_runtime.py:1677-1684`), while takeover requires a positive generation (`ops/runs/takeover.py:371-379`). Every isolated-browser CAPTCHA pause is therefore excluded from autonomous takeover. Add the generation to the strict summary and reject human-action responses without a positive service generation.

2. **HIGH — Browser generation mismatch corrupts the durable pause instead of remaining an inert CAS conflict — confirmed.** Canonical resume clears the HITL request and advances to `browser_running` before the isolated RPC (`ops/workflow/canonical_runtime.py:2587-2602`). A correctly rejected mismatch is converted to `human_action_required` without `hitl_generation`, projected as a new zero-generation pause, and only then raised as a takeover conflict (`ops/workflow/canonical_runtime.py:2654-2689`, `ops/workflow/canonical_runtime.py:1677-1684`, `ops/workflow/canonical_runtime.py:2240-2255`). Preserve the exact prior pause transactionally or treat the mismatch as inert ownership loss.

3. **HIGH — An unread final probe consumes its debt and makes the requested retry unauthorized — confirmed.** `observe_gate_clearance` clears matching debt even when `operation_in_flight` or `probe_failed` means no page was observed (`browser_service/clearance.py:68-101`). The decision then returns `keep_waiting` with `poll_again=True` because the report still says `final_probe_owed`, but the next poll has no authorization and suppresses the unchanged pause (`ops/browser/takeover.py:180-203`). Consume debt only after a completed same-generation observation.

Validation could not run because the available Python environments lack the project dependencies (`pydantic` and `pytest`); findings were verified by static end-to-end tracing of the current diff.
