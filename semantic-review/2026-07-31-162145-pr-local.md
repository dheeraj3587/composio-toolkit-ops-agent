# Autonomous CAPTCHA takeover and canonical route replanning

This change adds CAPTCHA clearance observation, an API takeover sweep, shared session expiry, canonical stale-run fencing, and preflight planning with one bounded replan. Liveness now waits beyond the outer browser RPC budget and commits stale state plus audits before browser release; takeover mutations bind revision, session, and gate. Three production blockers remain around proof of human participation and plan ownership. **Watch for:** **confirmed** unattached CAPTCHA clearance can resume a run; **confirmed** initial planning can create an unowned revision 2 that the replay path accepts; **confirmed** invalid replan outcomes bypass ownership CAS and can block newer same-effect state.

## High-level view

The takeover mutation is restricted to canonical CAPTCHA rows and guarded by revision, session, and gate. **Confirmed:** the sweep still probes every paused CAPTCHA, ignores `poll_again`, and accepts gate disappearance when neither an interactive grant nor the one owed final probe is present.

Canonical liveness uses `max(configured_staleness, ceil(browser RPC timeout) + 1)`, rechecks stale `updated_at` and running status, commits failure and both audits in one transaction, then releases the captured session. Stale takeover conflicts remain inert, and shutdown join is bounded by the clearance timeout.

The valid replan path performs model work before its transaction, then checks canonical status, exact state revision, and effect identity before committing plan supersession, attempt, projection, and audit together. **Confirmed:** initial-plan creation remains a cross-transaction check-then-write, and the revision-2 replay branch does not prove exact plan or effect ownership. **Confirmed:** planner refusal and malformed replacement paths return `False` before ownership CAS; the caller turns that into a block while its final guard omits the original revision.

## Unattached CAPTCHA disappearance authorizes continuation — **confirmed**

`RunTakeoverService.sweep` sends every canonical CAPTCHA pause through `_probe` without establishing an attached interactive grant (`ops/runs/takeover.py:136-174`, `ops/runs/takeover.py:207-229`). `decide_takeover` consults `attached` and `final_probe_owed` only for a still-present or unread gate; a different or absent gate returns `continue` unconditionally (`ops/browser/takeover.py:173-181`). The sweep never consumes `decision.poll_again`, so `stop_polling` is forgotten and the unattached run is probed again next interval.

A transient detector miss, page expiry, or navigation can therefore resume the canonical operation without evidence of human participation. Require current attachment or generation-bound final-probe authorization before accepting clearance, and keep unauthorized observations inert on later sweeps.

## Initial planning can manufacture an unowned revision 2 — **confirmed**

`plan_admission` reads for an active plan, calls the planner, then calls `record_plan` without a shared transaction or insert-if-absent condition (`ops/onboarding/driver.py:2267-2283`). The storage writer serializes each write but supersedes any active row and inserts `max(revision) + 1` (`ops/core/storage.py:2857-2892`). Concurrent initial callers can therefore record revisions 1 and 2 before any route divergence.

`replan_run_route` accepts any active row numbered 2 when the surface validator passes (`ops/runs/service.py:516-532`). It neither compares that row with the replacement just planned nor proves catalog id, recipe version, success digest, reason, or owning effect; `validate_plan` checks app slug and route surfaces, not those bindings (`ops/planner/validator.py:143-170`). An initial-race or otherwise unowned revision 2 can be accepted without the attempt/projection/audit transaction. Add an atomic “insert revision 1 if absent, otherwise reuse” operation, and reject a pre-existing revision 2 while the old run projection still matches.

## Invalid replans bypass stale-ownership handling — **confirmed**

`replan_run_route` returns `False` for planner refusal, a non-2 replacement, or validation failure before reading the run and comparing revision/effect ownership (`ops/runs/service.py:492-503`). `_route_adherence_override` maps `None` to an inert stale sentinel but maps `False` to a blocked outcome (`ops/workflow/canonical_runtime.py:1504-1530`). Its final projection guard checks session, broad status, and effect identity, not the `expected_state_revision` captured before planning (`ops/workflow/canonical_runtime.py:1932-1951`, `ops/workflow/canonical_runtime.py:1965-1973`).

If another callback replans the same effect while this planner returns an unusable result, the newer row retains the same session, `browser_running` status, and effect identity, so the stale callback can overwrite it with `route_divergence_unresolved`. Route every planner outcome through revision/effect CAS before choosing `False` versus `None`; ownership loss must remain inert.
