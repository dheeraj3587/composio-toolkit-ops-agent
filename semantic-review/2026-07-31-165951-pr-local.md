# CAPTCHA takeover and route ownership hardening (v2)

This pass rechecks the CAPTCHA watcher, plan admission, canonical replanning, and stale-run fencing against the prior findings. Atomic insert-or-reuse removes the concurrent revision-2 admission race, and unusable replans now pass through revision/effect ownership checks before they can block a run. Poll suppression honors `poll_again`, while canonical stale state and both audits commit before browser release. One production blocker remains: post-detach CAPTCHA authorization is not bound to the HITL generation whose attachment created it. **Watch for:** **confirmed** a final-probe grant from an earlier CAPTCHA can authorize a later CAPTCHA continuation with no operator attached.

## High-level view

Takeover now requires a current attachment or the one owed post-detach probe, and `stop_polling` is remembered against the exact revision/session/gate tuple. **confirmed:** the owed probe is still a bare session boolean; a new `hitl_generation` neither resets it nor participates in authorization.

Initial admission converges on revision 1 under `BEGIN IMMEDIATE`. Replanning checks canonical status, exact state revision, and effect identity before atomically committing plan supersession, attempt/projection, and audit; malformed or refused outcomes reach the same ownership check before returning `False`.

Canonical liveness places the stale boundary strictly beyond the outer browser RPC timeout, rechecks exact `updated_at` and running status transactionally, and releases the captured session only after failure and both audits commit. Shutdown join time is bounded, and sweep mutations do not change the immutable `created_at` pagination order.

Runs without an active plan remain outside adherence and replan handling, preserving the existing unplanned-run path.

## Final CAPTCHA authorization crosses HITL generations — **confirmed**

The final-probe debt is `ManagedSession.takeover_final_probe_owed: bool`, set when the last live-view attachment leaves (`browser_service/session_manager.py:158-168`, `browser_service/main.py:1150-1158`). A clearance read consumes it, but `_set_hitl_pending` only increments `hitl_generation` and changes `hitl_pending`; it never clears or rebinds the debt (`browser_service/clearance.py:67-96`, `browser_service/main.py:319-324`). Although the report carries the current generation, the watcher key contains only revision, session, and gate, and `decide_takeover` accepts `final_probe_owed` without a generation check (`ops/runs/takeover.py:223-239`, `ops/runs/takeover.py:329-343`, `ops/browser/takeover.py:182-190`).

```text
CAPTCHA generation 1: control client detaches -> final_probe_owed = true
owner resumes before watcher probes       -> hitl_pending = false; debt remains
provider returns another CAPTCHA          -> hitl_generation = 2; debt remains
clearance probe transiently sees no gate  -> attached = false, final_probe_owed = true
watcher continues generation 2
```

Generation 2 has no attributable attachment. A detector miss or challenge re-render can therefore advance a later human-only gate using participation from an earlier one. Bind the final-probe debt to the detach generation, clear it on every HITL transition, and require that generation to match the paused CAPTCHA metadata in the watch/CAS identity before `continue`.
